# 企业微信客户端安装与配置

本项目的安装与配置操作手册。所有命令与输出均在 2026-10-10 的本机实测过，实测值标注在本文第七节。

完整设计见 `docs/项目说明书.md`，日常聊天指令见 `README.md`。

## 一、安装前的三项准备

1. 安装 OpenCode 命令行。本项目实测版本 v2.0.22：
```
curl -fsSL https://opencode.ai/v2/install | bash
```
Homebrew 用户可用 `brew install anomalyco/tap/opencode-v2`。装完 `opencode --version` 能出版本号即可。
2. 确认本机 Python 版本不低于 3.8。本项目 venv 用的是 homebrew 的 Python 3.14.6。
3. 有一个企业微信企业账号，且在管理后台有创建智能机器人的权限。

## 二、创建机器人并拿到两个凭证

1. 企业微信管理后台，安全与管理，管理工具，智能机器人，创建机器人。
2. 选手动创建，拉到底部选 API 模式创建。
3. 先填名称和可见范围，保存。
4. API 配置区域选「使用长连接」。
5. 复制 BotID，点获取拿 Secret。
6. 长连接模式不需要填 URL、Token、EncodingAESKey，这三项留空。

官方协议文档：developer.work.weixin.qq.com/document/path/101463

关键限制三条，安装前先知道：每个机器人同时只能有一个有效长连接，新连接踢掉旧连接；每会话 30 条每分钟、1000 条每小时；流式消息从首次发送起 10 分钟内必须结束。

## 三、配置 .env

1. 复制模板：
```
cp .env.example .env
```
2. 必填四项，缺任何一项 `just_run.sh` 第 32 行会直接退出：

| 变量 | 填什么 |
|---|---|
| `WECOM_BOT_ID` | 机器人的 BotID |
| `WECOM_BOT_SECRET` | 长连接专用 Secret |
| `WECOM_DEFAULT_DIR` | 单聊默认项目目录，必须是已存在的真实目录 |

3. 全量配置项，未列默认值的按 `.env.example` 原样即可：

| 变量 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `WECOM_BOT_ID` | 是 | 无 | 机器人 BotID |
| `WECOM_BOT_SECRET` | 是 | 无 | 长连接专用 Secret |
| `OPENCODE_BASE_URL` | 否 | `auto` | 默认自动发现 opencode 共享服务；写显式地址时才连接指定服务 |
| `OPENCODE_USERNAME` | 否 | `opencode` | HTTP Basic 用户名 |
| `OPENCODE_PASSWORD` | 否 | 无 | 仅显式地址模式需要；`auto` 模式用服务登记文件里的密码 |
| `WECOM_DEFAULT_DIR` | 是 | 无 | 单聊默认目录，未配置的群一律拒绝执行 |
| `WECOM_GROUP_DIRS` | 否 | `{}` | 群聊目录映射，JSON 对象，键是群 chatid |
| `WECOM_ALLOWED_DIRS` | 否 | `[]` | 允许 `/proj` 切换的目录白名单，空数组即禁止切换 |
| `STREAM_MIN_CHARS` | 否 | 300 | 流式刷新字符阈值 |
| `STREAM_MIN_INTERVAL` | 否 | 2 | 流式刷新时间下限，秒 |
| `RENDER_MAX_CHARS` | 否 | 3000 | 单条消息字符上限 |
| `HEARTBEAT_INTERVAL_SEC` | 否 | 60 | 心跳间隔秒数，0 表示关闭 |
| `CONFIRM_TIMEOUT_SEC` | 否 | 300 | 权限确认超时秒数，超时视为拒绝 |

4. 三个最容易填错的地方：
    1. `OPENCODE_BASE_URL` 保持 `auto` 即可，地址与密码由 `~/.local/state/opencode/service.json` 提供。只有连接远端或独立服务时才写 `http://host:port`，那时 `OPENCODE_PASSWORD` 必填。
    2. `WECOM_DEFAULT_DIR` 不要指向临时目录，也不要留空。本项目实测填的是 `/Users/fanchuang/code/wx_apps`。
    3. `WECOM_GROUP_DIRS` 和 `WECOM_ALLOWED_DIRS` 是 JSON，必须是合法 JSON，单行写完，不要折行。空值写 `{}` 与 `[]`。

## 四、启动与停止

1. 在项目根目录执行：
```
./just_run.sh
```
macOS 也可以直接双击 `run_me.command`，它只做调用 `just_run.sh` 并保持终端不退出。
2. 脚本内部按顺序做五件事：建 venv、装依赖、校验 `.env` 三项必填、确认 opencode 共享服务就绪、最后启动 bridge。服务没起来时用 `opencode service start` 拉起，不另起一个 serve。
3. 2026-10-20 实测的启动日志：
```
[just_run] 检查 opencode 共享服务
[just_run] opencode 共享服务已就绪: http://127.0.0.1:19474
[just_run] 启动 bridge（已用 caffeinate 阻止系统休眠）
17:47:48 [INFO] 配置载入 base=http://127.0.0.1:19474 default_dir=/Users/fanchuang/code/wx_apps 允许目录数=0
17:47:48 [INFO] 已恢复 1 个会话映射
17:47:48 [INFO] [sdk#1] Establishing WebSocket connection...
17:47:49 [INFO] WebSocket 已连接
17:47:49 [INFO] bridge 已启动
17:47:49 [INFO] 事件订阅已建立
17:47:49 [INFO] [sdk#5] Authentication successful
17:47:49 [INFO] 订阅成功，开始接收消息
```
看到「订阅成功，开始接收消息」就是长连接通了。心跳间隔由 `HEARTBEAT_INTERVAL_SEC` 控制，默认 600 秒。
4. 停止按 Ctrl+C。bridge 自己捕获信号并退出，共享服务属于 opencode，脚本不会关闭它。
5. 不再有 `.serve_pid` 与 `opencode_serve.log`，这两个文件是旧版自行拉起 serve 时留下的。
6. 服务的地址会随 opencode 的配置变化，桥每次启动都重新发现，不写死端口。要手工查看执行 `opencode service status`。

## 五、装完怎么验证

1. 跑固化验证脚本，一条命令覆盖纯逻辑用例、空闲端口探测、全部 Python 文件语法自检、OpenCode 接口契约核对：
```
./tests/run_tests.sh
```
本次实测退出码 0，四个部分全过，其中接口契约部分输出「路径与权限决策枚举核对通过: ['once', 'always', 'reject']」，结束时按进程号关闭了它自己临时拉起的 serve。
2. 手机企业微信进入机器人会话，随便发一句话。首次进入会话会收到欢迎语，收到即代表链路通了。第二条起复用同一个 OpenCode 会话。

## 六、常见问题

1. 启动时报「缺少 .env，请先 cp .env.example .env 并填写」。按第三节第一节做。
2. 启动时报「.env 中某项未填写」。缺哪项填哪项，只查三项必填。
3. 启动时报「opencode 共享服务未就绪」。执行 `opencode service status` 与 `opencode service restart`，再看 `~/.local/share/opencode/log/opencode.log` 里的 `level=ERROR`。不要手动另起 `opencode serve` 绕开它。
4. 重新装依赖时报 bad interpreter。本项目 venv 是从旧目录名 `wecom_opencode_bridge` 下建出来的，`.venv/bin/pip` 的首行仍指向旧路径，直接调用会报 bad interpreter。当前 `.venv/.deps_ok` 已存在，脚本不会走这一分支，所以不影响启动。真要重装依赖时改用模块方式调用，实测可用：
```
.venv/bin/python -m pip install -r requirements.txt
```
5. 手机发了消息没有任何回复。先看 bridge 终端日志，正常会打印「收到消息 key=...」。没有这行说明长连接没通或可见范围不含这个账号；有这行但没有后续回复，说明卡在 OpenCode 侧。
6. 群里发消息机器人不理。三个原因：没有 @机器人；这个群没写进 `WECOM_GROUP_DIRS`；机器人可见范围没包含这个群。日志里会打印拒绝原因。
7. 回复被截断。单条上限由 `RENDER_MAX_CHARS` 控制，默认 3000 字符。超长会被截断并加提示。
